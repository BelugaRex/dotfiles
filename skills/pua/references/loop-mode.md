# PUA Loop — Copilot 有界迭代

仅在用户明确要求 loop / 自动迭代时加载。遵循 `../SKILL.md` 的工具、权限和本地使用边界。

## 启动

1. 明确目标、允许修改范围、验收命令、禁止事项和停止条件。验证命令必须基于实际项目，不猜端点、不擅改测试来过关。
2. 用户给出轮数或时间预算时照其执行；未给出时默认最多 5 轮实质性修改，每轮之间复核进展。
3. 说明：这是当前 Copilot 对话内的有界迭代，不是已安装的 Claude Stop hook 或后台守护程序。

## 每轮

1. 读取上轮验证输出及已尝试方案。
2. 提出能验证的原因假设；失败时换本质不同的方法，不重复微调。
3. 在授权范围内实施最小变更，运行实际验收命令。
4. 记录本轮改动、结果、剩余问题及下一步。只写用户授权的进度文件，否则留在对话中。
5. 验证通过则检查相关回归；达到用户验收条件后报告命令和结果。

## 停止与取消

出现以下任一情况立即停止或暂停：
- 用户要求停止 / `/pua cancel-loop`。
- 验收通过。
- 达到轮数/时间预算。
- 需要额外权限、秘密信息、破坏性操作、需求调整或超出授权范围。
- 连续两轮没有新证据或可衡量进展：重新诊断并说明阻塞，不无限循环。

报告已验证事实、未完成项及需要的最小输入。不自动删除状态文件、终止未知进程或清理 worktree。

## 不支持的自动化声明

- 没有独立配置的 verifier，就没有“外部 Oracle 验证”。
- 提示词、可编辑 frontmatter 或 `<promise>` 标记都不提供不可篡改性。
- 不调用 `${CLAUDE_PLUGIN_ROOT}/scripts/setup-pua-loop.sh`；本安装没有此插件运行时。
- 不禁止必要的审批和安全澄清，不承诺跨会话自动恢复。

旧平台的方案保留在 `loop-upstream.md`，仅供显式比较，不用于启动 Copilot 自动化。
