# PUA Pro — Copilot 本地模式

本说明替代旧插件的 Pro 入口。先遵循 `../SKILL.md` 的平台边界；所有数据默认留在当前对话，不自动注册、上报或写入长期状态。

## KPI / 复盘

用户请求 `/pua KPI`、`/pua pro`、周报或述职时：

1. 从当前任务记录提取目标、改动、实际验证命令与结果、未覆盖风险。
2. 需要代码变更记录时，先只读检查目标仓库和相应时间段；不把其他仓库/无关会话纳入。
3. 用 `display-protocol.md` 的相关展示格式或用户要求的简表输出，不编造分数、测试数、节省时间、团队数量或成长基线。
4. 区分“自己验证通过”“用户验收通过”和“尚未验证”。周报的包装不能改变证据含义。

建议字段：目标 / 实施 / 验证证据 / 结果 / 剩余风险 / 下一步。

## 风格

- 用户选择 flavor 时读取 `flavors.md` 以及对应方法文档。
- 用户选择 mama 或 yes 时读取相应模式，两者互斥。
- 普通选择只影响当前会话；设为默认须用户明确授权修改具体文件。

## 状态与续接

Copilot 不会因加载 skill 自动执行 Claude 的 PreCompact 或 SessionStart hook。

- 需要续接时，先读取用户指定的项目计划/进度记录，再核对实际文件和验证结果。
- 可以在用户已授权的项目进度文件中记录已验证事实、尝试过的方法和下一步。
- 不默认创建或修改 `~/.pua/evolution.md`、`builder-journal.md` 或其他长期基线。
- 失败次数不是对用户的评分；问题解决后恢复正常语气。

## 本地配置与反馈

`on/off/offline` 只改变当前会话行为，不声称启停了客户端 hooks。反馈和 survey 默认在对话中完成；保存本地文件或上传都需明确授权。

旧平台的订阅、排行榜、登录和遥测不是本地技能的前置条件。`pro-upstream.md` 仅供用户明确要求比较上游设计时参考，不自动执行其联网步骤。
