# PUA Copilot 运行契约

本参考用于解决旧版 PUA 内容与当前 VS Code Copilot 宿主能力不一致的问题。先执行 `../SKILL.md` 的授权和本地使用边界；本文件不启用插件功能。

## 能力边界

- 技能文本不会创建文件系统、终端、网络、子代理或模型能力。仅使用当前会话真实提供且已获准的工具。
- 本安装没有注册生命周期 hooks、自动状态注入、后台任务、确定性 stop gate 或独立 verifier。`SessionStart`、`PreCompact`、`PostToolUse` 等仅是旧平台术语。
- 不因 `~/.pua/` 路径出现在旧文档就读取、创建或修改其中内容；须有用户对具体操作的明确授权。模式变化默认只在当前对话有效。
- 默认不联网，不注册账号，不收集电话/邮箱/凭据，不支付，不请求或上传会话/代码/路径/遥测。用户另行提出外部操作时，先说明数据、目的地和副作用并取得明确授权。
- 不调用 Claude CLI、Anthropic SDK 或其他外部模型/压缩服务。Caveman 压缩候选由当前 Copilot 产生。

## 执行与验收

对每个子目标简记：目标与验收信号、已验证事实、已排除假设、真实失败实验、味道是否锁定、下一步。无需公开内部思维草稿。

- 只有真实执行了新实验且约定结果未成立，才为该子目标增加一次失败计数。相同日志重复展示不重复计数；读取成功、`grep` 无匹配或退出码本身都不自动等于成功或失败。
- 测试刻意复现原缺陷是复现证据，不是修复失败。文件读取/命令成功而目标仍未验收，不是突破、不清零、不降压。
- 失败时改变因果假设或实验，而不是只改参数、名字或措辞。新证据能回答验收问题时复用，不为清单标题重复测试。
- 子目标验收真实通过才标完成；运行受阻则标明已验证部分、具体阻塞与最小解锁动作。不得把计划、候选、自测或提示词描述成外部裁定。

## 风味锁定与恢复

用户明确要求某一风味后，在本任务中保持该风味。失败路由可更换方法论，不得改写风味。只有用户明确解除锁定或要求自动路由时，才恢复自动选择。

状态仅在当前对话或用户明确指定的任务记录中维护。宿主未提供历史时，写“历史计数未知”，从当前可见事件起算；不要假装自动跨会话恢复，也不要自动沉淀到长期记忆。

## 突破与换框

突破必须由当前子目标验收信号证明，而非 Bash exit code、hook 注入或任意工具成功。确认 L2+ 子目标突破后，可将其压力归零、使用已锁定风味的认可话术，并用一两句总结有效方法；持久化经验仍需用户授权。各层换框是当前对话中的建议，不是 hook 注入。
